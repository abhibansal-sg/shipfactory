ShipFactory — The Work Matrix

DRAFT FOR ATTACK · six category-agnostic axes · a recipe = one coordinate in this space · 23 Jul 2026

1 · The Six Axes

Every unit of governed work — code, procurement, research, ops — is a point in this space. The axes are orthogonal: picking a value on one never forces a value on another. "Software dev" is not an axis; it is a coordinate.

2 · A Recipe Is a Coordinate, Not an Architecture

Three real work categories plotted on the same axes. dev-pipeline@14 — the thing we built 14 versions of — is ONE row. Everything it needed (worktrees, sandboxes, evidence bundles) is machinery for ITS coordinates, not the spine.

3 · What the Matrix Forces: Spine vs Coordinate Machinery

The audit rule that falls out: anything true at EVERY point of the space is spine. Anything true only at some coordinates is pluggable machinery that must declare its coordinates. Today several coordinate-machineries are welded into the spine.

Rules of the matrix

  • • Axes must stay orthogonal — any forced pairing is an axis error
  • • A recipe = one coordinate; a workflow = a path of coordinates
  • • Combinations get marked: real / rare / impossible
  • • Impossible cells need a reason (e.g. external effect + retry-same without journal = forbidden)

What this buys

  • • Engine audit becomes mechanical: map each module to cells
  • • "Engine flattening" gets a precise meaning: coordinate machinery in the spine
  • • New work categories = new rows, zero new architecture
  • • Seat/skill tuning becomes per-cell, not per-anecdote

Held invariant (not up for attack)

  • • Human approval gate at every coordinate — the One Law
  • • Count-caps only, never token budgets
  • • Immutable published recipes
  • • External effects only through the intent journal
